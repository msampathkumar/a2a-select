# `a2a-select` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `a2a-select`, an interactive CLI and `a2a` command plugin for discovering agents in an ARDS registry, managing and verifying local A2A Agent Cards, and running stateful multi-turn A2A chat conversations with full `taskId` and `contextId` lifecycle management.

**Architecture:** Modular Go CLI application (`go 1.25+`, standard library only) structured into four testable core packages (`internal/a2acli`, `internal/cards`, `internal/ards`, `internal/session`) and an interactive line-driven controller (`internal/ui`), wired together in `main.go` with support for the `a2a` Command Plugin `info` contract.

**Tech Stack:** Go (`encoding/json`, `os/exec`, `net/http`, `bufio`, `flag`, `testing`).

**Spec:** `docs/superpowers/specs/2026-10-16-a2a-select-design.md`

## Global Constraints

- Zero external third-party Go module dependencies (100% Go standard library).
- Never invoke shell interpolation (`sh -c`); pass discrete argument slices to `exec.CommandContext` after validating the `a2a` binary path.
- Enforce directory boundary checks (`filepath.Clean` + trailing separator prefix check) on all local Agent Card file writes and reads.
- Persist session state (`0o600`) and directories (`0o700`) with least-privilege file permissions.
- Every new function/method must follow strict TDD (write failing test -> watch it fail -> write minimal code -> watch it pass).

## Review Focus

1. **Completed task continuation bug:** Sending a follow-up message after a task reaches `TASK_STATE_COMPLETED` (or `completed`) must NOT pass `--task-id`; it must pass `--context-id` only so a new task is created in the same context.
2. **Interrupted task continuation:** Sending a follow-up message when the task is in `TASK_STATE_INPUT_REQUIRED` or `TASK_STATE_AUTH_REQUIRED` MUST pass both `--task-id` and `--context-id`.
3. **Both v1.0 (`supportedInterfaces`) and v0.3 (`url`) Agent Cards:** Extracting the live verification URL from a saved Agent Card must handle both v1.0 `supportedInterfaces[0].url` and legacy v0.3 top-level `url`.
4. **Unreachable remote agent during card verification:** If `a2a card get` fails during verification of a saved local card, the user must be able to continue with the cached local card rather than crashing.
5. **Path traversal via untrusted Agent Card names from ARDS or remote servers:** An agent card named `../../etc/passwd` must be sanitized into a safe filename slug strictly inside `cardsDir`.

### Automated Security Check
- **Security Scanner**: Run a scan on all newly created files using the `run-security-scanner` skill to identify common vulnerabilities (e.g., command injection, path traversal, SSRF, hardcoded secrets). If findings are detected, auto-apply the fix and document the results.
- **Security Audit**: Audit the new code against `mandatory-secure-web-skills` guidelines:
  - System Command Execution: Validate `a2a` binary path and pass argument arrays directly to `exec.CommandContext` without a shell.
  - Path & File System Security: Sanitize agent card names with `filepath.Base` and strict slugging; verify resolved paths stay within `cardsDir + string(filepath.Separator)`.
  - Testing: All test HTTP servers (`httptest.NewServer` and `a2a server --echo`) bind strictly to `127.0.0.1` / `localhost`, never `0.0.0.0`.
  - Document findings and remediations in the `walkthrough.md` artifact using the `generate-security-audit-report` skill.
